Website Migration SEO: How to Protect Organic Traffic During a Redesign

A redesign should improve your website, not erase years of organic visibility — here is how to plan the move step by step.

MT

Miaoon Strategy Team

Nov 3, 2026 · 9 min read

Summary
  • Website migration can involve changes to URLs, domains, hosting, platforms, or website structure.
  • Without SEO planning, a redesign can lead to broken pages, indexing problems, and traffic loss.
  • URL mapping, relevant redirects, technical checks, and monitoring help reduce migration risks.
  • SEO should be involved before the new website goes live, not only after problems appear.

A website redesign is often planned to improve appearance, user experience, speed, or business functionality. However, a new design can also change URLs, page layouts, navigation, content, and technical settings. If these changes are not handled carefully, a business may lose organic traffic that took months or years to build.

This is why SEO needs to be part of the migration process from the beginning.

At Miaoon, businesses can approach website growth with a focus on both visibility and performance. A redesign should improve the website without unnecessarily damaging the organic presence of existing pages.

What Is Website Migration in SEO?

Website migration refers to significant changes to a website that can affect how search engines access, understand, or index its pages.

Common examples include:

  • Moving from one domain to another.
  • Changing URL structures.
  • Switching a website to a new CMS.
  • Moving from HTTP to HTTPS.
  • Redesigning the website and changing its page hierarchy.
  • Combining multiple websites into one.

Google's guide to site moves explains how to prepare URL changes and reduce their impact on Search results. Even when the domain stays the same, changes to important page URLs and internal links should be planned carefully.

Why Website Redesigns Can Affect Organic Traffic

1. Existing URLs Are Changed

A page that previously ranked well may have a different URL after the redesign. If the old URL is removed without a suitable redirect, visitors and search engines may encounter a not-found error.

2. Important Content Is Removed

Sometimes redesign projects shorten pages or remove sections to create a cleaner layout. However, removing useful information can affect the page's ability to answer search queries.

Review existing content before removing it. Keep useful information and improve its presentation rather than deleting it simply because the new design has less space.

3. Search Engine Access Is Blocked

Development websites are sometimes protected using "noindex" settings or robots.txt rules. These settings must be reviewed before launch.

Google's documentation on robots.txt and noindex directives explains how these controls affect crawling and indexing.

4. Internal Links and Sitemaps Are Not Updated

A redesigned website may still contain links to old URLs. The XML sitemap may also include pages that no longer exist.

Google recommends updating internal links and submitting a sitemap containing the new URLs as part of a planned site move.

How to Protect SEO During a Website Migration

Step 1: Record Existing Website Performance

Before making changes, collect a record of important URLs, organic landing pages, search queries, backlinks, and conversions.

Use Google Search Console to review clicks, impressions, indexing information, and search performance. Use Google Analytics to understand which landing pages bring visitors and valuable actions.

You can also use Google Looker Studio to organise reporting dashboards and compare performance over time.

Step 2: Create an Old-to-New URL Mapping

Prepare a spreadsheet listing important existing URLs and their corresponding new destinations.

Every old URL that is changing should be reviewed. Redirect it to the most relevant equivalent page, not automatically to the homepage.

For large websites, crawling tools such as Screaming Frog and Sitebulb can help collect URLs and identify technical issues.

Step 3: Set Up Relevant 301 Redirects

When a page permanently moves to a new URL, a server-side permanent redirect such as a 301 is generally recommended.

Avoid redirect chains and irrelevant redirects. Google advises keeping redirects in place for a long period—generally at least one year for a site move—and updating internal links to point directly to the new URLs.

The HTTP status code reference from MDN can help developers understand the meaning of redirects and other response codes.

Step 4: Check Canonical Tags and Indexing Settings

Every important page should have an appropriate canonical URL. Check that canonical tags point to the correct new pages and that important pages are not accidentally marked "noindex".

Google's canonical URL guide explains how canonicalisation helps consolidate signals for duplicate or similar URLs.

Step 5: Update Internal Links and XML Sitemaps

Replace old internal URLs with their new destinations. Check navigation menus, footer links, blog links, images, and other resources.

Create and submit an updated XML sitemap using the sitemap guidelines. Make sure it contains the preferred, indexable URLs rather than redirected or blocked pages.

Step 6: Test the New Website Before Launch

Do not wait until launch day to discover problems. Test the staging website for:

  • Broken links and missing pages.
  • Incorrect redirects.
  • Mobile usability.
  • Page loading speed.
  • Canonical tags and indexing directives.
  • Navigation and important forms.
  • Images, scripts, and other resources.

Use PageSpeed Insights and Chrome Lighthouse to review performance and user experience.

Step 7: Monitor the Website After Launch

Once the migration is live, monitor the old and new URLs. Check indexing, crawl errors, redirects, organic clicks, impressions, and conversions.

Use the URL Inspection Tool to investigate individual pages. Review the Search Console sitemap report to understand how Google processes submitted sitemaps.

For domain changes, review the Change of Address guidance and follow the process when applicable.

Common Website Migration SEO Mistakes

  • Launching without a URL mapping document.
  • Redirecting every deleted page to the homepage.
  • Forgetting to remove staging-site "noindex" settings.
  • Leaving internal links pointed at old URLs.
  • Removing useful content without reviewing its performance.
  • Forgetting to update the sitemap and canonical tags.
  • Stopping monitoring immediately after launch.

A migration may involve temporary ranking fluctuations while search engines recrawl and process the changes. The aim is to prevent avoidable errors and monitor recovery rather than assume that every fluctuation means the migration has failed.

Frequently Asked Questions

Does a website redesign affect SEO?
It can. Changes to URLs, content, navigation, page speed, internal links, and indexing settings may affect search visibility. Careful planning and testing can reduce avoidable problems.

How long does SEO recovery take after migration?
There is no fixed recovery period. Google notes that processing a site move can take weeks or longer, depending on website size, crawling, server performance, and the scale of the changes.

Should every old URL redirect to the homepage?
No. Redirect each old URL to the most relevant equivalent new page. Sending unrelated pages to the homepage can confuse visitors and may be treated as a soft 404.

Do I need to submit a new sitemap after migration?
Yes, when URLs have changed, submit an updated sitemap containing the preferred new URLs. This helps Google discover the new URL structure.

Should SEO work start before or after the redesign?
SEO planning should start before development and launch. It is much easier to preserve URLs, content, and technical settings when SEO requirements are included in the project from the beginning.

Conclusion

A website migration is more than a design or development task. It can affect the URLs, content, navigation, and technical foundations that support organic search traffic. Preparing a URL map, implementing relevant redirects, checking indexing settings, updating internal links, and monitoring performance can help reduce migration risks.
